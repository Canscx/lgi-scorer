# 宝塔部署教程 · 小巨人自评系统

从「服务器还是空的」到「浏览器打开域名看到登录页」。每一步都带验证点，做完一步确认一步，不要跳。

> **与专精特新站（8787）共存**：本项目固定用 **8788** 端口、`lgi` 前缀（目录、pm2 名、备份目录）。
> 两个站可以装在同一台服务器上，互不干扰，但**每个站的 Node 实例数都必须是 1**。

## 0. 部署前清单

| 项 | 要求 | 没有它会怎样 |
|---|---|---|
| 服务器 | 2 核 4G 起，已装宝塔面板 | 2G 内存解析大 PDF 会直接崩 |
| 域名 | 已购买并解析到服务器 IP | 只能用 IP:端口访问 |
| 备案 | 国内服务器必须备案；境外不用 | 备案没下来 80/443 被拦 |
| 宝塔插件 | Node 项目管理器（网站 → Node项目） | 找不到添加入口 |
| 端口 | **8788** 未被占用 | 启动失败，换端口即可 |

检查端口占用：

```bash
ss -lntp | grep 8788
```

## 1. 上传代码

宝塔「终端」里执行（推荐 git，以后更新一条命令同步）：

```bash
cd /www/wwwroot
git clone <你的仓库地址> lgi
cd lgi
```

用 zip 上传也行，但**压缩包里绝不能包含** `node_modules`、`data`、`release`、`.tmp` —— 前两个几百 MB 且跨机器必坏，后两个属于本机私有产物。

验证：`ls /www/wwwroot/lgi` 能看到 `server`、`web`、`config`、`package.json`。

## 2. 安装 Node 22 与 pnpm

宝塔 → 软件商店 → Node.js 版本管理器 → 安装 **v22**（LTS）。

**不要用 v26 或更新的 Current 版本。** 项目里 `@napi-rs/canvas` 是预编译二进制，新 ABI 未必有对应包，`pnpm install` 当场报错。22 是经过完整验证的版本。

```bash
node -v          # 应显示 v22.x
npm i -g pnpm
pnpm -v          # 应显示 11.x
```

## 3. 安装依赖并构建

```bash
cd /www/wwwroot/lgi
pnpm config set registry https://registry.npmmirror.com   # 国内加速，可选
pnpm install
pnpm build
```

三条纪律：

1. `pnpm install` **不能加 `--prod`** —— `tsx` 在 devDependencies 里，过滤掉服务起不来
2. `pnpm build` 必须出现 `✓ built in` 字样
3. 构建后 `ls web/dist` 应看到 `index.html`

## 4. 安装中文字体

导出 PDF 需要中文字体。如果这台机器上专精特新站已经装过，**可以直接跳过这一步**（两个站共用系统字体）。检查：

```bash
fc-list | grep -i -E 'noto.*cjk|wqy|simhei' | head -3
```

没有就三选一：

**A. Ubuntu / Debian**

```bash
apt install -y fonts-noto-cjk
```

**B. RHEL / CentOS / OpenCloudOS / 麒麟**

```bash
dnf install -y wqy-zenhei-fonts
```

**C. 直接放字体文件**（没有包管理器权限时最稳）

宝塔「文件」进入 `/www/wwwroot/lgi`，新建 `fonts` 目录，把 `simhei.ttf` 传进去即可，不用配环境变量。

装完做一次自检，它会列出所有候选并真的生成一张中文 PDF：

```bash
cd /www/wwwroot/lgi
pnpm check:font
```

看到「结论 PDF 导出可用」才算这一步完成。改完字体重启 Node 项目生效。

## 5. 配置登录密码

在项目根目录创建 `.env` 文件（宝塔「文件」里右键新建），可参考同目录 `.env.example`：

```
AI_API_KEY=
AI_BASE_URL=https://api.deepseek.com/v1
AI_MODEL=deepseek-flash

AUTH_USER=admin
AUTH_PASSWORD=改成你的密码

AUTH_CUSTOMER=customer
AUTH_CUSTOMER_PASSWORD=改成发给客户的口令

PORT=8788
DATA_DIR=./data
```

两个账号分两个入口，登录页「我是客户 / 管理员」就是切这两个：

- **admin** 进后台：上传、确认页、评分页、客户提交总览、模型设置
- **customer** 进轻流程：填企业信息、传材料、一键评估、看结果、下报告

不建 `.env` 也能跑，走内置默认值（`admin/abc123456/` 与 `customer/vip666666`）；**开放访问前一定改掉这两个默认密码**，尤其 customer —— 它会被发给客户。

**AI Key 有两种填法**：页面右上角「模型设置」（优先级高，不用重启），或 `.env` 里的 `AI_API_KEY`（重启生效）。默认接 DeepSeek。

## 6. 宝塔添加 Node 项目

网站 → Node项目 → 添加Node项目，逐项填写：

| 字段 | 填什么 | 说明 |
|---|---|---|
| 项目目录 | `/www/wwwroot/lgi` | 指到代码根目录，不是 /www/wwwroot |
| 项目名称 | `lgi` | 之后日志里用，**不要和 srdi 重名** |
| 启动选项 | 自定义命令：`node_modules/.bin/tsx server/src/index.ts` | 见下方「两个必改」 |
| Node版本 | v22 | 不要用默认的 v26 |
| 包管理器 | pnpm | |
| 不安装node_module | **勾选** | 第 3 步已装好，让宝塔再装会出岔子 |
| 运行用户 | www | 默认 |
| 项目端口 | **8788** | 服务真实监听端口，**必须与专精特新站的 8787 错开** |
| 绑定域名 | 你的域名 | 会自动生成反代 |

**两个必改的默认值：**

- **启动选项别选"自动获取"**。它会执行 `pnpm build && ...`，以后每次重启都重新构建前端，失败一次整个服务起不来。自定义命令只负责拉起进程。
- **Node 版本别用 v26**。理由见第 2 步。

点确定后看项目状态变「运行中」。如果启动失败，点项目日志，九成是 Node 版本或依赖没装全。

## 7. 验证服务活着

```bash
curl http://127.0.0.1:8788/api/health
```

返回里应该能看到：

```json
"service": "lgi-scorer"
"rules": { "id": "rules.lgi.v1.0.0", "level": "LITTLE_GIANT", "gates": 9, "indicators": 23 }
"runtime": { "port": 8788 }
```

此时浏览器打开域名，应该能看到**登录页**——现在就能登录进系统用了。

> 注意：这是**另一个站**。如果页面上方标题是「专精特新申报自评打分系统」而不是「小巨人申报自评打分系统」，说明你打开的是专精特新站（8787），不是本项目。

剩下的步骤是修正体验与补上证书，不完成也能跑，但别省。

## 8. 修正反向代理

宝塔自动生成的反代缺两样东西：

- 上传 50MB 的 PDF 会报 413（nginx 默认只放行 1MB）
- 解析进度条永远不动（SSE 被缓冲了）

网站 → 设置 → 配置文件，找到 `#PROXY-START/` 到 `#PROXY-END/`，**整段替换**为本项目 `deploy/nginx-site.conf` 的内容，然后：

```bash
nginx -t && nginx -s reload
```

替换后验证：登录 → 上传一份样本材料 → 点解析 → **进度条会动**。

**不要用面板的「加密访问」「反向代理」按钮改这块** —— 前者会让反代失效（输完密码白屏），后者会覆盖你手改的配置。

## 9. SSL 证书

网站 → 设置 → SSL → Let's Encrypt → 勾选域名 → 申请 → 开「强制 HTTPS」。

强制 HTTPS 是硬要求，不是锦上添花。

## 10. 日常更新

本地改完代码后：

```bash
pnpm validate     # 本地，提交前必跑
git push
```

服务器上一条命令：

```bash
bash deploy/update.sh
```

脚本会从自己所在位置反推项目根目录，然后依次：备份当前代码 → 拉代码 → 同步依赖 → 构建前端 → `pnpm check:font` → 重启服务 → 健康检查。全程约一分钟，`data/` 不受影响。

备份落在 `/www/backup/lgi/lgi-code-<时间>-<提交>.tar.gz`，默认留最近 10 份。

**改坏了怎么退回去：**

```bash
bash deploy/rollback.sh --list   # 看有哪些快照
bash deploy/rollback.sh          # 恢复最近一份
```

回滚会保留 `node_modules`、`data`、`.env`、`fonts`，不会把数据带走。

## 11. 与专精特新站共存时的检查清单

| 检查项 | 本项目 | 专精特新站 |
|---|---|---|
| 站点目录 | `/www/wwwroot/lgi` | `/www/wwwroot/srdi` |
| 进程端口 | 8788 | 8787 |
| pm2 进程名 | `lgi` | `srdi` |
| 备份目录 | `/www/backup/lgi` | `/www/backup/srdi` |
| 实例数 | **1** | **1** |
| 规则包 | `rules.lgi.v1.0.0.json` | `rules.srdi.v1.0.0.json` |
| 数据目录 | `/www/wwwroot/lgi/data` | `/www/wwwroot/srdi/data` |

**最容易踩的三个坑：**

1. 两个站都设成同一个端口 → 后启动的那个失败。用 `ss -lntp | grep -E '8787|8788'` 确认。
2. 两个站都用 `srdi` 作为 pm2 名 → 重启时把另一个站也重启了。本项目统一用 `lgi`。
3. AI Key 共用时额度是分开记的（各自记在自己 `data/projects/<id>/ai-usage.json`），没有全局限额。要控成本就各自配 Key。

## 12. 数据备份

所有项目、材料、打分结果都在 `/www/wwwroot/lgi/data` 一个目录里。

宝塔 → 计划任务 → Shell 脚本，每天凌晨执行：

```bash
tar -czf /www/backup/lgi-$(date +\%F).tar.gz -C /www/wwwroot/lgi data
find /www/backup -maxdepth 1 -name "lgi-*.tar.gz" -mtime +7 -delete
```

保留最近 7 天。`-maxdepth 1` 不能漏：代码快照放在 `/www/backup/lgi/` 子目录里，不加这个参数会连它们一起删掉。

## 13. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| Node 项目启动即停 | 用 `--prod` 装了依赖 | 重跑 `pnpm install` 再重启 |
| 启动报端口占用 | 8788 被别的程序占了 | `ss -lntp | grep 8788` 找出占用，或改 `.env` 的 PORT |
| 登录页之后白屏 | 用了面板「加密访问」 | 删掉它，重套 `nginx-site.conf` |
| 传 PDF 报 413 | 反代没改 | 做第 8 步 |
| 进度条不动 | SSE 被缓冲 | 做第 8 步 |
| 页面显示「专精特新申报自评打分系统」 | 打开的是**另一个站**（8787） | 确认域名解析与反代端口指向 8788 |
| 导出 PDF 报 500 `report_font_missing` | 缺字体 | 做第 4 步，再 `pnpm check:font` |
| 结果页没有「七项认定指标」区块 | 跑的是旧构建 | `pnpm build` 后重启；或清浏览器缓存 Ctrl+F5 |
| 登录一直失败 | 密码不对或 Cookie 被拦 | 核对 `.env` 的 `AUTH_PASSWORD` / `AUTH_CUSTOMER_PASSWORD` |
| 域名打不开 | 备案或解析问题 | `ping 域名` 看解析；国内服务器查备案 |

更多细节见 `deploy/README.md`；改动记录见 `docs/PLAN.md` 第十一节。
