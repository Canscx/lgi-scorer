## 一、政策核查结论（这一节推翻了你给的部分表格）

我派研究员查了工信部原文，结论如下。**凡与三张对照表不一致的，以官方原文为准**，理由附在每处。

### 1.1 原文出处

- 《优质中小企业梯度培育管理办法》**工信部企业〔2026〕2号**，成文 2026-01-04，发布 2026-01-16，**2026-04-01 施行**
  通报正文：https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2026/art_5546b1a622ea4d73bd2ca395b73bd4eb.html
  中国政府网：https://www.gov.cn/zhengce/zhengceku/202601/content_7055453.htm
- 附件 1（专精特新中小企业标准）/ 附件 2（小巨人标准）/ 附件 3（指标解释）**未以网页形式挂在工信部站上**，已从两个政府站点转载逐字核对：
  湖南省工信厅转载：https://gxt.hunan.gov.cn/gxt/xxgk_71033/zcfg/gjjfg/202606/t20260615_34002090.html
- 工信部政策解读：https://www.miit.gov.cn/zwgk/zcjd/art/2026/art_208fb27917cf4740b27974e6fe428042.html

### 1.2 小巨人认定标准原文（附件 2，需同时满足以下七项指标）

| # | 原文 |
|---|---|
| 一 | 已获得专精特新中小企业称号，截至上年末从事特定细分市场时间达 3 年以上 |
| 二 | 上年度营业收入总额达 5000 万元以上，主营业务收入总额占营业收入总额比重不低于 90%。近两年营业收入复合增长率不低于 5%（**复核企业不考查该项指标**），上年末资产负债率不超过 75% |
| 三 | 近两年研发费用合计不低于 1200 万元，且**每年**占营业收入比重均不低于 3% |
| 四 | 拥有 **4 项以上**与主导产品相关的 Ⅰ类知识产权，且实际应用并已产生经济效益。对近三年获得**国家级**科技奖励（排名前三）的企业，不考察本项指标 |
| 五 | 主导产品在国内或国际细分市场占有率达到 10% 以上或国内前三名，且享有较高知名度、影响力 |
| 六 | 主导产品属于制造业核心基础零部件、核心基础元器件、关键软件、先进基础工艺、关键基础材料、产业技术基础，或属于改造提升传统产业、培育壮大新兴产业、布局建设未来产业，位于产业链关键环节 |
| 七 | 本年度中小企业专精特新发展评价得分达 **60 分**以上（复核企业近两年任意一年达 60 分以上即可） |

### 1.3 与你那三张表的五处出入

| # | 你表上的说法 | 官方原文 | 影响 |
|---|---|---|---|
| ① | 评价体系是「四大维度：专业化/精细化/特色化/创新能力」 | **五大维度**，成长性是一级维度。工信部解读原文：「从专业化、精细化、特色化、创新能力、成长性等方面设置 20 余项指标」 | 参考项目的 5 维度 23 项**本来就对**，不用改成 4 维度。这条反而省事 |
| ② | 表中未提 | 附件 3（十）：评价**不包含加分项** | 不设任何手工加分入口 |
| ③ | 奖励豁免写「国家级」（这条你表里是对的） | 复核确认：**小巨人只认国家级**；**省部级奖励豁免只存在于专精特新中小企业**（附件 1） | 不能照搬专精特新站的 GATE_4，它接受省部级 |
| ④ | 研发费用「近两年合计 ≥1200 万」 | 正确，且**每年**占营收比 ≥3% 是另外单独一条 | 拆成两道门槛，见 3.2 |
| ⑤ | Ⅰ类知识产权「≥4 项，自主申请且权利人排名前三」 | 正确，附件 3（七）落地为「**不包含转入**，且**在权利人中排名前三**」 | 转入专利必须被排除，字段上要能区分 |

另有三条对工具很重要的补充：

- **市场占有率「企业如实说明即可」**（附件 3 四），2026 年申报通知明确免交占有率证明 → 不应要求客户上传第三方证明，客户自述即可，报告标注「自述」。
- **主导产品定义**（附件 3 三）：主导产品收入之和占营业收入比重 **超过 50%**。
- **复核便利**（附件 3 十一）：企业按自身所获**最高一级**称号参加复核。

### 1.4 权重问题（必须让你知道）

工信厅企业〔2024〕75 号《中小企业专精特新发展评价指标体系（试行）》的**附件表与权重表未公开上网**。工信部解读只说「通过培育平台套用公式自动计算得出」，23 项三级指标的明细与各维度权重**没有官方原文可引**。

二手来源给出的权重是 **专业化 15 / 精细化 20 / 特色化 15 / 创新能力 35 / 成长性 15**，与参考项目 `rules.srdi.v1.0.0.json` 现有的五个维度权重**完全一致**。

→ **这意味着参考项目的权重设置可以直接沿用**，但必须在报告显著位置写：维度权重来自二手来源，官方未公开，参考得分不可用于申报材料中的自评分数填报。

还有一处**对不上的地方**需要说明：中国政府网转载光明日报提到「设置 23 个指标，其中 4 个指标考察企业知识产权情况，**权重为 18%**」。参考项目 23 项里与知识产权直接相关的只有 IND_03、IND_14、IND_17、IND_18 四项，排除 IND_18 后重归一约 14.2%，与 18% 有差距，但「4 个指标」这个数量吻合。是否校准见 **待确认项 Q1**。

### 1.5 新申请 / 复核 两套规则

工信厅企业函〔2026〕117 号明确：2026 年度新申请按 2026 年《办法》；**本年度申请复核的小巨人仍按 2022 年 63 号文把握**。

两套规则对小巨人的实际差异只有两处：

| 项 | 新申请 | 复核 |
|---|---|---|
| 近两年营收复合增长率 ≥5% | 考查 | **不考查** |
| 评价得分 ≥60 分 | 本年度 | **近两年任意一年达标即可** |

→ 做成评估时的一个选项（默认「新申请」），见 3.6。

## 二、产品定位与形态

### 2.1 一句话

**给准备申报（或想自查）专精特新“小巨人”的企业，上传几份材料，几分钟内得到「七项认定指标逐条判定 + 五维参考得分 + 差什么、补什么」。**

### 2.2 双角色

| 角色 | 入口 | 看到什么 |
|---|---|---|
| **客户 customer** | 域名根路径 | 填企业信息 → 传材料 → 一键评估 → 结果页 → 下载 PDF |
| **管理员 admin** | `#/admin` | 客户提交总览、确认页（改证据）、评分页（看 23 项）、重算、导报告、模型设置 |

客户侧**不出现**：API 配置、23 项原始数字、保守分、证据确认页、规则假设全文。

### 2.3 客户侧 5 屏

```
① 登录页
② 首页      企业名 + 手机 + 统计截止年 + 申报类型(新申请/复核) + 知识产权件数 + 8 个材料槽
③ 评估中    阶段进度 + 排队位次
④ 结果页    七项门槛逐条 + 当前分 / 60 分线 + 五维横条 + 差多少补什么 + PDF 下载
```

## 三、打分模型

### 3.1 三层结构（沿用参考项目，已证明可用）

```
第一层  认定门槛   逐条 pass / fail / unknown / pending，全过才有资格
第二层  23 项得分   五维加权求和，得 official / conservative / optimistic 三口径
第三层  得分门槛   official ≥ 60 判达标（复核用近两年任一）
```

### 3.2 十二道门槛（七项原文 → 可判定的十二项）

| ID | 门槛 | 判据 | 类型 | 官方依据 |
|---|---|---|---|---|
| G1 | 已获专精特新中小企业称号 | `company.srdiTitle == true` | **硬门槛** | 附件2-一 |
| G2 | 细分市场深耕 ≥3 年 | `company.subMarketYears >= 3` | **硬门槛** | 附件2-一 |
| G3 | 上年度营收 ≥5,000 万 | `revenue[y0] >= 50000000` | **硬门槛** | 附件2-二 |
| G4 | 主营收入占比 ≥90% | `mainBusiness/revenue >= 0.90` | **硬门槛** | 附件2-二 |
| G5 | 资产负债率 ≤75% | `ratio[y0] <= 0.75` | **硬门槛** | 附件2-二 |
| G6 | 近两年营收复合增长率 ≥5% | `CAGR(y0, y1) >= 0.05` | **硬门槛**（复核自动豁免） | 附件2-二 |
| G7 | 近两年研发合计 ≥1,200 万 | `rd[y0] + rd[y1] >= 12000000` | **硬门槛** | 附件2-三 |
| G8 | 研发占营收比每年 ≥3% | `rd[y0]/rev[y0]>=0.03 && rd[y1]/rev[y1]>=0.03` | **硬门槛** | 附件2-三 |
| G9 | Ⅰ类知识产权 ≥4 项 | `count(I where selfApplied && rank<=3 && !transferredIn) >= 4` | **硬门槛**（国家级科技奖豁免） | 附件2-四 |
| G10 | 市场占有率 ≥10% 或国内前三 | `qual.marketRanking ∈ {ge10, national_top3}` | **提示项** ← 你选的 | 附件2-五 |
| G11 | 六基 / 产业链关键环节 | `qual.chainKey == true` | **提示项** ← 你选的 | 附件2-六 |
| G12 | 评价得分 ≥60 | `official >= 60`（复核：y0 或 y1 任一） | **硬门槛** | 附件2-七 |

「提示项」的语义与硬门槛不同：**不影响达标结论**，只在结果页单列一块「主观项提醒」，并说明「官方口径为企业如实说明即可，本工具不作否决」。

**每道门槛在 `config/rules/rules.lgi.v1.0.0.json` 里带 `enabled` 与 `severity: hard | advisory` 两个字段**，你在 config 里改一个布尔值就能关掉，不用改代码（这是你选的方案）。

### 3.3 23 项指标（几乎全盘沿用，逐项核对过适用性）

| 维度 | 权重 | 项数 | 小巨人是否沿用 | 说明 |
|---|---|---|---|---|
| 专业化 | 15 | 4 | 全部沿用 | 细分市场年限、细分行业排名、发明专利集中度、标准制修订 |
| 精细化 | 20 | 6 | 全部沿用 | 含 QMS 认证、产品权威认证 |
| 特色化 | 15 | 4 | 全部沿用 | 含数字化水平、绿色化称号、PCT |
| 创新能力 | 35 | 6 | 全部沿用 | 研发投入/占比、知识产权档位、研发机构、研发人员 |
| 成长性 | 15 | 3 | 全部沿用 | 营收/利润/净资产增长率 |

**只有三处需要为小巨人调整**：

1. **IND_17 知识产权档位**：专精特新站按「就高五档 10/8/6/2/0」。小巨人硬门槛要求 **≥4 项**，档位表重排为「≥4 项且高价值 = 10 分 / ≥4 项自主研发 = 8 分 / ≥1 项 Ⅰ类 = 6 分 / 仅 Ⅱ类 = 2 分 / 无 = 0 分」，**把 4 项红线嵌进档位**，避免出现「门槛不过但该项满分」的自相矛盾。
2. **IND_18 专利点度中心度**：继续排除（需专利引文库，第三方不可得），沿用 `exclude` 策略，权重重归一。
3. **IND_02 细分行业排名**：继续中性 0.5 估算，因为 G10 已是提示项，不宜在分数里二次惩罚。

### 3.4 得分门槛三态

| 条件 | verdict | 结果页措辞 |
|---|---|---|
| `official ≥ 60` | pass | 已过 60 分参考线 |
| `official < 60 ≤ optimistic` | pending | 有条件达标，取决于 N 项待补证指标 |
| `optimistic < 60` | fail | 未达线，需补强 Top 差距 |

客户版另有**证据覆盖率 ≥50%** 的前置要求，防止全缺证据时恰好 60 分被误判达标（沿用参考项目 `MIN_PASS_CONFIDENCE`）。

### 3.5 权重与假设（透明声明）

报告与结果页必须同时出现这三条：

1. 维度权重为二手来源（15/20/15/35/15），**官方未公开**
2. 三级指标维度内等权，**官方未公开**
3. 参考得分**不可**用于申报材料中的自评分数填报，最终以培育平台计算为准

### 3.6 新申请 / 复核切换

评估时的一个字段 `applicationType: 'new' | 'review'`，落进 evidence.json，影响两处：

- G6 复合增长率：`review` 时 verdict 强制为 pass，并打 `GATE_SKIPPED_FOR_REVIEW` 标
- G12 得分门槛：`review` 时用「近两年任一达标」判定，需要**上一年度得分**

上一年度得分从哪来：客户在首页填一个可选数字（上次自查或平台公布的分数）。不填则用当前年度。见 **Q2**。

## 四、材料槽位（8 个）

| # | 槽位 | 必传 | 对应门槛 / 指标 | 说明 |
|---|---|---|---|---|
| 1 | 营业执照 | 否 | — | 自动识别经营范围 / 注册资本 / 成立日期，写进报告封面 |

| 4 | 企业所得税年度申报表 | 是 | 研发费用最硬证据 | 最好带加计扣除明细表 A107012 |
| 5 | 账簿与科目余额表 | 否 | 研发费用归集核验 | 财务软件导出 Excel |
| 6 | **市场占有率说明** | 否 | **G10（提示项）** | 官方「如实说明即可」，模板下载即可，不用第三方证明 |

新增的 3 个槽（#2 #6 #7）都是小巨人特有，直接对应硬门槛，缺了就在结果页明确告诉客户「这一项卡住了」。

首页做**前置闸门**：一份材料都不传也允许评估（客户可能只想看分数），但要弹一次「没有专精特新证书，G1 会判定为不满足，这条是小巨人的一票否决项」。

## 七、宝塔部署方案

### 7.1 与参考项目共用一台服务器的差异点

| 项 | 参考项目 | 本站 |
|---|---|---|
| 站点目录 | `/www/wwwroot/srdi` | `/www/wwwroot/lgi` |
| 进程端口 | 8787 | **8788** |
| 反向代理 | 域名 → 127.0.0.1:8787 | 新域名 → 127.0.0.1:8788 |
| pm2 进程名 | srdi | **lgi** |
| 备份目录 | `/www/backup/srdi` | `/www/backup/lgi` |
| 数据目录 | `/www/wwwroot/srdi/data` | `/www/wwwroot/lgi/data` |
| Node 版本 | v22 | v22（同一个） |
| 中文字体 | 已装 | 复用同一套系统字体，不用重装 |

### 7.2 部署步骤（对齐参考项目的手把手教程）

1. 宝塔 → 网站 → 添加站点，域名填新域名（占位 <你的域名>），纯静态即可
2. 上传代码到 `/www/wwwroot/lgi`
3. `cd /www/wwwroot/lgi && pnpm install && pnpm build`（**不能加 --prod**，tsx 在 devDependencies）
4. 中文字体：复用现有（`fc-list` 能看到 Noto CJK / 文泉驿即可），`pnpm check:font` 自检
5. 写 `.env`（见 7.3）
6. 宝塔 → Node 项目 → 添加：目录 `/www/wwwroot/lgi`，启动命令 `node_modules/.bin/tsx server/src/index.ts`，端口 **8788**，**实例数 1**，不勾「安装 node_modules」
7. 反向代理整段替换为 `deploy/nginx-site.conf`（含 `client_max_body_size 60m` 与 `proxy_buffering off`）
8. SSL → Let's Encrypt → 强制 HTTPS
9. `curl http://127.0.0.1:8788/api/health` 验证

### 7.3 .env 模板

```
AI_API_KEY=                       # 页面里也能填，页面配置优先
AI_BASE_URL=https://api.deepseek.com/v1
AI_MODEL=deepseek-flash

AUTH_USER=admin
AUTH_PASSWORD=改成你的密码

AUTH_CUSTOMER=customer
AUTH_CUSTOMER_PASSWORD=改成发给客户的口令

PORT=8788
DATA_DIR=./data
```

> 你已确认：**页面里能填，环境变量里也能填，默认接 DeepSeek**。优先级沿用参考项目：页面配置 > 环境变量 > 默认值。

### 7.4 本次部署要额外注意的三点

1. **端口 8788 不需要在宝塔「安全」里放行** —— nginx 反代走本机回环，只监听 127.0.0.1:8788 即可，不要开公网端口。
2. **两个站共用一个 AI Key 时**，token 消耗各自记在自己的 `data/projects/<id>/ai-usage.json`，没有全局额度。要控成本就各自配 Key。
3. **两个站的规则包版本独立**。改了 `config/rules/` 之后，**已经出过分的项目不会自动重算**（项目创建时绑定了规则版本），这是刻意设计。
