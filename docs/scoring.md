# 打分模型

> 23 项指标的参数在 `config/rules/rules.lgi.v1.0.0.json`,本文只写**为什么这么算**。

## 一、判定分三层

```
第一层  九项门槛   逐条 pass / fail / unknown / pending
                  7 道硬门槛全过才有资格；2 道提示项不参与结论
第二层  23 项得分  加权求和,得三口径区间
第三层  得分门槛  GATE_9 用 official 判是否 ≥60 分(乐观口径兜底为 pending)
```

门槛与得分完全独立。**硬门槛不过,分数再高也没用**;硬门槛全过,分数不到 60 一样不通过。

### 硬门槛与提示项的区别

| 类型 | 数量 | 是否影响结论 | 未通过时 |
| --- | --- | --- | --- |
| `hard` 硬门槛 | 7 | **是** | `aggregateConclusion` 判 fail/pending |
| `advisory` 提示项 | 2（GATE_7 市占率、GATE_8 产业链） | **否** | 只进「主观项提醒」区块 |

提示项之所以不做否决，是因为官方附件 3 明确「企业如实说明即可」，2026 年申报通知亦免交占有率证明。做成硬性否决会系统性误伤材料齐全但未写说明的企业。

### 三种门槛开关

规则包的每道门槛支持三个开关，全部在 `config/rules/` 里改，不用动代码：

| 字段 | 作用 | 用在 |
| --- | --- | --- |
| `enabled: false` | 整道门槛跳过，判 pass 并打 `skipped` | 口径有疑问想临时关掉某条 |
| `severity: 'advisory'` | 不进结论，只进提醒 | GATE_7 / GATE_8 |
| `reviewExempt: true` | 复核类型下强制 pass | GATE_4 复合增长率 |

研发费用门槛的"近两年"指上年度(y0)与前年度(y1)，与 GATE_2 的营收口径一致。

## 二、权重归一

**官方未公开维度权重表。** 工信厅企业〔2024〕75 号的附件未上网，工信部解读只说「通过培育平台套用公式自动计算得出」。

规则包采用的是二手来源给出的五个维度权重，与专精特新站完全一致：

```
w_i = 维度权重 × share_i / Σshare        Σw_i ≡ 100
```

`share` 默认全为 1，即维度内等权：

| 维度 | 权重 | 项数 | 单项分值 |
| --- | --- | --- | --- |
| 专业化 | 15 | 4 | 3.75 |
| 精细化 | 20 | 6 | 3.33 |
| 特色化 | 15 | 4 | 3.75 |
| 创新能力 | 35 | 6 | 5.83 |
| 成长性 | 15 | 3 | 5.00 |

这条假设的后果：**参考得分与培育平台的计算结果不可直接比对。** 要调整权重，改 `share` 即可，不用改代码。

> 中国政府网转载光明日报提到「设置 23 个指标，其中 4 个指标考察企业知识产权情况，权重为 18%」。本工具 23 项里与知识产权直接相关的 IND_03 / IND_14 / IND_17 / IND_18 排除 IND_18 后重归一约 14.2%，与 18% 有差距但数量吻合。经确认为**不做校准**，如实声明即可。

## 三、小巨人与专精特新的三处指标差异

| 项 | 专精特新 | 小巨人 |
| --- | --- | --- |
| IND_17 知识产权档位 | 就高五档 10/8/6/2/0（Ⅰ类 ≥1 项即可高档） | **4 项红线嵌入档位**，见下表 |
| IND_18 专利点度中心度 | 排除，权重重归一 | 同上 |
| IND_02 细分行业排名 | 中性 0.5 估算 | 同上（GATE_7 已单独做提示项，不在分数里二次惩罚） |

IND_17 档位（满分 10，不叠加）：

| 条件 | 得分率 | 含义 |
| --- | --- | --- |
| Ⅰ类 ≥4 项且高价值 | 10 / 10 | 同时满足门槛与最高档 |
| Ⅰ类 ≥4 项且自主研发 | 8 / 10 | 满足门槛 |
| Ⅰ类 ≥4 项 | 7 / 10 | 满足门槛 |
| Ⅰ类 1–3 项 | 3 / 10 | **未达门槛**，分数也压低 |
| 仅Ⅱ类 | 1 / 10 | 不满足门槛 |
| 无 | 0 | — |

把 4 项红线嵌进档位，是为了避免「门槛不过但该项满分」的自相矛盾。

## 五、七种打分器

| type | 输入 | 输出 | 用于 |
| --- | --- | --- | --- |
| `piecewise` | 一个数值 | 分段线性插值的得分率 | 1, 14, 15, 16 |
| `tier` | 表达式条件 | 首个命中的档位分 ÷ maxPoints | 9, 10, 17, 19 |
| `benchmark` | 企业值 + 行业基准 | 超均值映射曲线 | 5, 6, 7, 8, 11, 21, 22, 23 |
| `formulaSum` | 若干计数 × 系数 | 求和 ÷ cap | 4, 13 |
| `hhi` | IPC 分布 | 赫芬达尔指数 → 插值 | 3 |
| `composite` | 多个子打分器 | 加权合成 | 20 |
| `manualTier` | 人工枚举选择 | 档位分 ÷ maxPoints | 2, 12 |

`tier` 是**顺序求值、首个命中即返回、不累加**,因为指标 9 官方明确"以最高分为准,不重复累加"。指标 17 同理:知识产权按就高五档(10/8/6/2/0)选一档,Ⅱ类只在无Ⅰ类时兜底 2 分。

## 六、B 类映射曲线(核心)

设企业值 `x`、行业基准 `b`:

```
δ = (x - b) / b                正向指标
δ = (b - x) / b                逆向指标(费用率)

δ > 0:  s = base + (1 - base) × min(δ / kUp, 1)
δ ≤ 0:  s = base × (1 + δ / kDown)
```

默认 `base=0.60, kUp=0.50, kDown=1.00`,即:

| δ | 得分率 | 含义 |
| --- | --- | --- |
| -1.00 | 0.00 | 低于均值 100%(即 x=0)归零 |
| -0.50 | 0.30 | 只有均值一半 |
| 0.00 | 0.60 | **等于均值拿 0.6** |
| +0.25 | 0.80 | 高出均值 25% |
| +0.50 | 1.00 | 高出 50% 满分 |
| +1.00 | 1.00 | 触顶保持 |

曲线连续、单调、有界。唯一断点在 δ=0 处一阶导变化,可接受。

**为什么基准值不是 0.5 而是 0.6?** 因为这套体系的方向是"超均值即得分",均值本身应视为及格线而非中位线。0.6 让"刚好达标"的企业不至于被误判为不合格。

## 七、边界保护(必须实现)

否则会算出荒谬结果:

| 场景 | 处理 |
| --- | --- |
| 净资产 ≤ 0 | ROE 不计分,打 `negative_equity`,`status=notApplicable` |
| 产品销售成本 ≤ 0 | 记 `missing`,不按 0 计算 |
| 基期为负、本期为正 | 增长率直接记 1.0,打 `base_negative` |
| 基期为正、本期为负 | 增长率直接记 0.0,同上打标 |
| 基期为负、本期更负 | 记 0.0,不用 `(x-b)/b` |
| 分母为 0 | 记 `missing`,不打 0 |

## 八、三口径

```
official      = Σ w_i × s_i                     C 类按中性 0.5
conservative  = Σ w_i × s_i   (估算/缺失一律记 0)
optimistic    = Σ w_i × s_i   (估算/缺失一律记 1)
confidence    = 1 - Σ w_i(信用不足项) / 100
```

门槛 6 的判据由 `totalKey` 决定,当前配 `official`(政策原文的"评价得分"就是这一个口径,conservative / optimistic 是我们自造的下限与上限,不能拿来当判据):

| 条件 | verdict | 报告措辞 |
| --- | --- | --- |
| `official ≥ 50` | pass | 已过 50 分参考线,补齐缺口还能再提 |
| `official < 50 ≤ optimistic` | pending | 有条件达标,取决于 N 项待补证指标 |
| `optimistic < 50` | fail | 未达线,需补强 Top 差距 |

`totalKey` 写什么,`passLine` 就按那个口径比;想改回保守判定只需把 `totalKey` 改成 `conservative`,代码不用动。

客户版"达标"还要求证据覆盖率 ≥50%(`confidence`),防止全缺证据时 official 恰好 50 被误判。

**信心与分数分离**:证据置信度低只降 `confidence` 和打标,不二次缩放分数。双重惩罚会让分数失去可解释性。

## 十、手算样例(C35 专用设备制造)

企业:营收 13200 / 11800 / 9600 万,研发 520 / 430 / 380 万,净资产 6000 / 5500 / 5100 万,净利润 720 / 650 / 600 万,员工 312 人。

口径提示:凡公式里带 `mean(...)` 的,一律先对三年取均值再算。所以人均营收是「三年均营收 ÷ 人数」,ROE 是「三年均净利 ÷ 三年均净资产」,不是拿最新一年去除。这一点在 `shared/test/golden.spec.ts` 里有测试锁死。

| 指标 | 计算 | 得分率 |
| --- | --- | --- |
| 21 营收增长率 | (13200−11800)/11800 = 11.86%;基准 8% → δ=0.4825 | 0.6+0.4×0.965 = **0.986** |
| 6 ROE | 656.7/5533.3 = 11.87%;基准 9% → δ=0.3185 | 0.6+0.4×0.637 = **0.855** |
| 5 人均营收 | 11533.3万/312 = 36.97 万;基准 150 万 → δ=−0.7536 | 0.6×0.2464 = **0.148** |
| 16 研发占比 | mean(3.94%, 3.64%, 3.96%) = 3.85% | 0.25+0.424×0.2 = **0.335** |
| 15 研发投入 | mean(520,430,380) = 443.3 万 | 0.55+0.717×0.15 = **0.658** |
| 3 专利集中度 | (4/6)²+(2/6)² = 0.556 | **0.956** |
| 9 质量认证 | 仅 ISO9001 → 1/10 | **0.100** |

单指标得分 = `w_i × s_i`。如指标 21 落在成长性维度(单项 5 分),贡献 `5 × 0.986 = 4.93` 分。

注意指标 5 与 6 的反差:**ROE 高于同行,人均营收却只有同行四分之一**。这正是补强建议要抓的信号 —— 人效低意味着产能未释放或人员结构冗余,而不是盈利能力问题。

## 十一、口径假设

完整清单在 `rules.json` 的 `assumptions` 字段,报告页同步展示。核心六条:

1. 三级指标维度内等权(官方未公布)
2. 指标 4 标准计分上限按 10 分设定
3. 指标 13 绿色化每项 +0.5,上限 2 分
4. 指标 17 取官方就高五档:高价值Ⅰ类 10 / 自主研发Ⅰ类 8 / Ⅰ类 6 / Ⅱ类 2 / 无 0
5. B 类映射曲线参数为工具设定
6. 行业基准为公开数据估算,非官方

## 十二、序列年份对齐(2026-11)

`mean()` / `sum()` 必须在同一批年份上取数,否则分子分母样本集不同,比值失真。

- `deriveFormula` 用 `formula.inputs` 的全部序列字段求**槽位交集**,写入 `EvalEnv.align`
- `mean` / `sum` 只取交集内 `state==='ok'` 的槽位;交集为空 → `missing`
- 交集不满三年 → `partial_window`(`quality=estimated`)
- 兜底:比值尺度(基准 ≤5)且 `|raw| > 5` → `outlier_ratio`,报告加「基期偏小」提示

影响 IND_05 / 06 / 07 / 08 / 11。实例(2023–2025):

| 序列 | 可用年份 | 均值 |
| --- | --- | --- |
| `fin.revenue` | 2023=0 / 2024 / 2025 | 5,024,121.62 |
| `fin.operatingCost` | 2025 | 14,070,665.19 |
| 修复前 | 分母 3 年、分子 1 年 | **−180.06%** |
| 修复后 | 只取 2025 | **4.50%** |

## 十三、补齐并达标情景(客户展示)

客户报告页的「补齐并达标后」不是引擎三口径,是展示用目标分。

- 逐项:`excluded` 记 0;`absent / substituted` 记满权重;`notApplicable` 记 0;其余取 `max(实际贡献, 0.8 × 有效权重)`
- 维度与总分同口径求和,总分 clamp 0–100
- `goal ≥ official` 恒成立,雷达图与横条不会倒挂
- 只用于客户报告页与客户版 PDF,不参与 GATE_6 判定,不写入 `score-result.json`

为什么单独设:引擎的 `optimistic` 只对「缺证据」展开,对「有数据但分数低」不展开。特色化这类维度会变成当前分与补齐后分重合,客户看不出改善空间。实拍项目 `p_mvyvijzbcce4e3ea`:特色化 `0.43 → 12.74`,总分 `45.46 → 88.98`。
